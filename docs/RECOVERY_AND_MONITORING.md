# التشغيل والتعافي — بُعد

النطاق: BUOD Staging فقط، 28 سبتمبر 2026. هذا دليل تنفيذ وقبول، لا إثبات تشغيل مراقبة مستمرة أو نجاح استعادة.

## الحالة المثبتة

- المشروع `uhcvfwajowdszxteanlx` سليم ويستخدم الخطة المجانية. صفحة Database Backups تنص على أن الخطة لا تشمل النسخ الاحتياطية، وتعرض الترقية المدفوعة. لم تُنفذ ترقية.
- الاختبارات الآلية تعمل عند تحديث staging، وليست مراقبة لتوافر الخدمة بين التحديثات.
- يوجد فحص قراءة محدود: `BUOD_LIVE_STAGING=1 npm run test:staging-health`. يرفض مشروعًا آخر أو مفتاح خادم، ويرسل 30 طلبًا بحد أقصى 3 متزامنة، دون حسابات أو تعديل بيانات. يتوقف بعد الدفعة التي تفشل؛ يرجع رمز خروج غير صفري عند فشل أو P95 أعلى من ثانيتين. لا يثبت سعة إطلاق أو SLA.
- يمكن ربط الفحص لاحقًا بمراقب معتمد بعد اختيار مسؤول التنبيه وقناته. لا توجد حاليًا قناة تنبيه مستمرة مفعّلة بهذه الإضافة.

## بوابة النسخة الاحتياطية

1. يحدد المالك فقد البيانات المقبول (RPO) ومدة التعافي المقبولة (RTO) ويعتمد الميزانية والمكان المشفر للاحتفاظ بالنسخ.
2. اختيار نسخ مدارة مناسبة أو عملية تصدير مستقلة موثقة. لا تحفظ ملفات النسخ أو مفاتيحها في Git، ولا تنقلها لخدمة جديدة دون تصريح.
3. الاحتفاظ بنسخة متسقة من البيانات والمخطط والأدوار اللازمة، وإعدادات المصادقة والروابط والبريد بصورة لا تكشف المفاتيح.
4. **ملفات Storage لها نسخة مستقلة:** نسخة قاعدة Supabase لا تحتوي بايتات الملفات؛ تحتوي بياناتها الوصفية فقط. الاحتفاظ بقائمة الكائنات والحجم والبصمة SHA-256 ضمن عملية النسخ، والتحقق من وجود بايتاتها في النسخة المنفصلة.
5. تسجيل توقيت النسخة ومعرف المشروع وإصدار قاعدة البيانات وآخر ترحيل، ومراقبة فشل النسخ وعمر أحدث نسخة ناجحة.

## تمرين الاستعادة المعزول

- استعادة إلى مشروع اختبار فارغ ومعتمد، لا فوق staging الحالي أو الإنتاج. يتطلب تجهيز الهدف وصلاحياته؛ لا ينشئ هذا الدليل اشتراكًا أو مشروعًا مدفوعًا.
- تعطيل الإرسال الحقيقي للبريد في بيئة الاستعادة واستخدام بيانات اختبار، وعدم إعادة استخدام جلسات أو أسرار الإنتاج في المتصفح.
- التحقق من تطابق سجل الترحيلات، وعدد الصفوف والعلاقات، ومفاتيح الملكية، وبصمات عينة من ملفات Storage.
- تنفيذ `supabase/tests/workspace_security.sql` و`supabase/tests/admin_security.sql` داخل معاملات التراجع، ثم قبول حي بهويات مؤقتة مع تخصيص أدوات الفحص للهدف المستعاد صراحةً؛ الأدوات الحالية تمنع غير staging.
- تجربة تسجيل دخول وحفظ ورفع وتنزيل ورفض حساب آخر، وتوثيق الزمن الفعلي وفجوة البيانات من النسخة. لا تسجل كلمة مرور أو رابط مصادقة أو مفتاح في تقرير الإثبات.
- لا يعتمد نجاح الاستعادة على رسالة «اكتمل» وحدها. لا يُفتح الموقع قبل توقيع المسؤول على النتائج وخطة العودة.

## سياسة التنبيه المقترحة لاعتماد المالك

| الحدث | استجابة التشغيل |
|---|---|
| فشل فحص التوافر المتكرر أو ارتفاع أخطاء الخدمة | تأكيد العطل من جهة ثانية ثم تنبيه المسؤول مع الوقت ومعرف النشر، دون بيانات حسابات |
| ارتفاع P95 عن خط الأساس | مقارنة المنطقة والشبكة وعدد الطلبات وخطة الحوسبة، وعدم توسيع الحمل تلقائيًا |
| خطأ المتصفح أو فشل 3D | جمع رمز خطأ وإصدار التطبيق ونوع المتصفح؛ عدم جمع نماذج المستخدم أو روابط التنزيل أو تسجيل الجلسة افتراضيًا |
| فشل نسخة احتياطية أو تجاوز عمرها المعتمد | إيقاف اعتماد الإطلاق حتى استعادة نسخة سليمة واختبارها |
| تجاوز صلاحيات أو كشف بيانات | إيقاف المسار المتضرر وحفظ الأدلة الآمنة وتفعيل خطة الاستجابة؛ لا حذف للسجلات |
