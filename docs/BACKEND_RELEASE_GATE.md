# بوابة إغلاق الباك إند — BUOD Staging

آخر تحقق: 12 أكتوبر 2026. النطاق: `staging` فقط. لا تغيير على `main` أو الإنتاج.

## معيار الإغلاق

يعتمد هذا القرار على دفاع متعدد الطبقات بدل الاعتماد على مزود واحد: OWASP ASVS 5.0 لمتطلبات أمان التطبيق، NIST SSDF 1.1 لدورة التطوير الآمن، عقد PostgreSQL للصلاحيات وRLS، وإرشادات Supabase الحالية للتشغيل. الإغلاق يعني أن الكود والمخطط واجتياز الاختبارات جاهزة للانتقال إلى عمل الواجهة؛ ولا يعني شهادة امتثال أو إلغاء الحاجة إلى مراجعة مستقلة قبل الإطلاق العام.

## نتيجة البوابة

| المجال | الحالة | الدليل |
|---|---:|---|
| عزل البيانات | ناجح | كل جداول API عليها RLS، وكل عروض `public` تستخدم `security_invoker` |
| صلاحيات الإدارة | ناجح | ستة تطبيقات مرتفعة الصلاحية داخل `private` خلف واجهات `SECURITY INVOKER`؛ اختبار الرفض واختبار المدير المصرح نجحا |
| أقل صلاحية | ناجح | الزائر للقراءة فقط، ودور الحساب غير قابل للتعديل من العميل، وحاويات BUOD خاصة |
| تغييرات المستقبل | ناجح | Default privileges بنمط deny-by-default للجداول والتسلسلات والدوال الجديدة |
| سجل المخطط | ناجح | 57 ترحيلًا محليًا وبعيدًا؛ آخر نسخة `20261012165202` موثقة ببصمة SHA-256 |
| أسرار المتصفح | ناجح | اختبار انحدار يمنع أي مرجع لمفتاح `service_role` داخل `src` |
| مستشار قاعدة البيانات | ناجح للمخطط | لا تحذير أمني هيكلي بعد الترحيل؛ ملاحظات الأداء معلوماتية عن فهارس جديدة لم تُحذف بلا قياس |
| سجلات آخر 24 ساعة | ناجح | لا رسائل مطابقة لـ error أو fatal أو panic وقت الفحص |
| مسار الكتالوج | ناجح من جهة الخادم | 28 طلبًا مسجلًا، صفر استجابة غير 200؛ P95 عند أصل Supabase نحو 747ms والحد الأقصى 805ms. بطء عميل الفحص المعزول لم يظهر داخل الخادم |
| اعتماديات التشغيل | ناجح | `npm audit --omit=dev --audit-level=low`: صفر ثغرات معروفة في الحزم المنشورة |
| أدوات بناء الواجهة | مؤجل للفرونت | تنبيه DoS انتقالي في سلسلة Tailwind 3؛ إصلاح npm المقترح ترقية كاسرة إلى Tailwind 4، فلا يُخلط بتغيير أمان الباك إند دون مراجعة بصرية كاملة |
| التعافي التشغيلي | **قرار مطلوب** | المشروع Free؛ لا نسخة يومية مُدارة قابلة للاستعادة ولا اختبار استعادة معزول |
| حماية كلمات المرور المسرّبة | **قرار مطلوب** | الميزة تحتاج Supabase Pro؛ هي تحذير Auth الوحيد المتبقي |

## أوامر إعادة التحقق

```bash
npm run check
npm audit --omit=dev --audit-level=low
```

وشغّل على قاعدة staging بصلاحية مسؤول، داخل معاملات تنتهي بـ `ROLLBACK`:

- `supabase/tests/admin_security.sql`
- `supabase/tests/backend_contract.sql`
- `supabase/tests/workspace_security.sql`

بعد أي ترحيل: طابق `supabase/migrations/manifest.json` مع سجل Supabase، ثم شغّل مستشاري الأمن والأداء وفحص النشر الحي.

## تعريف القرار

- **Backend code complete:** نعم، بعد نجاح الفحص النهائي والنشر.
- **Production operations complete:** لا، حتى اعتماد خطة مدفوعة، تفعيل حماية كلمات المرور المسرّبة، إعداد نسخة بيانات وStorage خارجية أو نسخ مُدارة، وتنفيذ اختبار استعادة فعلي في بيئة معزولة.
- يمكن بدء تطوير الواجهة بأمان على staging مع إبقاء بوابة التشغيل أعلاه شرطًا قبل نقل `main` أو الإطلاق العام.
