### Rollback and recovery

A failed migration transaction rolls back; verify history and schema before retrying. On frontend failure, roll back to the recorded staging frontend SHA or disable admin editing while investigating. Keep the hardened backend: old RPCs remain, but old clients that call the now-private audit RPC may show failures, and old two-request publication must not be resumed as a normal workflow. Prefer a reviewed forward fix; do not reopen profile/audit/storage vulnerabilities. A database restore is a separate owner-approved recovery action with a write freeze and explicit handling of post-backup transactions, Auth state, audit retention and Storage metadata/object consistency. There is intentionally no automatic destructive down migration.
